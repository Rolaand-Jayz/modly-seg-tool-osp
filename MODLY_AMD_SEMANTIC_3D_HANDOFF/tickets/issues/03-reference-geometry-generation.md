# 03 — Select and integrate the reference geometry generator

**What to build:** Turn a source image into a canonical geometry artifact on the RX 7900 GRE through a replaceable Modly `Generate Geometry` adapter. Probe Hunyuan3D 2 Mini/Turbo and the strongest plausible 16 GB alternative, select the reference implementation using measured AMD viability/quality/porting cost, and write the result plus reproducible provenance into the Structured Asset.

**Blocked by:** 01 — Structured Asset headless round-trip; 02 — AMD Runtime proof through Modly.

**Status:** acceptance passed — Hunyuan3D-2 Mini/Turbo was selected after the frozen three-fixture AMD screen; TripoSR failed the frozen silhouette gates.

- [x] Before final comparison, the generator probe declares the correctness/quality thresholds and selection rubric; Hunyuan3D 2 Mini/Turbo and the plausible TripoSR alternative are measured for AMD dependencies, peak VRAM, latency, output validity/quality, and porting work on the RX 7900 GRE. Evidence: frozen rubric and `api/runtime/adapters/geometry/evidence/triposr-candidate/`, plus the Hunyuan per-fixture evidence below.
- [x] The selected generator accepts a source observation through Modly and emits a valid geometry artifact plus Structured Asset update. The manifest contract remains generic (`observation` input; geometry/structured-asset/stage-artifacts outputs); the implementation emits vendor identity only as Structured Asset provenance.
- [x] The dense Hunyuan denoiser region was qualified for Torch-MIGraphX; its target MIGraphX result was slower than PyTorch ROCm (692.82 ms vs 418.04 ms), so the supported explicit full-module ROCm path was selected. The same pinned source, weights, device, module architecture, dtype, inference profile and fixed 512x512 input shape apply to all three fixture images; their tensor values differ, but this dense region has no data-dependent control flow. Each fixture provenance records that it reused the matching region-level rejection. TripoSR's MIGraphX output failed declared tolerance, so its full ROCm fallback was used.
- [x] No custom 3D GPU primitive was introduced; Hunyuan's marching-cubes extraction uses the adapter-local CPU scikit-image implementation. No shared HIP seam is warranted by this ticket's measured path.
- [x] The adapter enables upstream model CPU offload and completes all three fixed fixtures within 14 GiB board VRAM and the 180-second post-load generation limit, without weakening the fixed detail profile or quality thresholds.
- [x] Provenance includes pinned source/weight revisions and digests, backend/runtime, observation identity, parameters, seed, device, generation latency, and VRAM. Each result marks geometry from one image as model-inferred and the image as observed evidence.
- [x] Failed generation preserves pre-existing Structured Asset bytes and publishes neither GLB nor sidecar; `test_adapter_failure_publishes_no_geometry_or_sidecar_and_preserves_prior_asset` also asserts the run staging directory is removed. Invalid GLBs likewise are not registered.
